# pi-merge-gateway-login

[pi](https://github.com/earendil-works/pi-mono) extension that adds the [Merge Dev gateway](https://docs.merge.dev/merge-gateway/) as a model provider through its [OpenAI Responses API](https://docs.merge.dev/merge-gateway/).

## Install

```bash
pi install npm:@iaziz786/pi-merge-gateway-login
# or from git:
pi install git:github.com/iAziz786/pi-merge-gateway-login
```

Then authenticate (prompts for your key, stores it in `~/.pi/agent/auth.json`):

```
/login merge-gateway
```

Permissions: outbound HTTPS to `api-gateway.merge.dev` only. No filesystem or subprocess access. Key stored by pi in `~/.pi/agent/auth.json`.

## Models

Nine model IDs across four gateway models, in two kinds:

- **Host-pinned** ids carry the host as a vendor prefix (`particle/…`, `fireworks/…`). The extension pins the host in the request body, so pi's cost display matches the host that bills. The pin rides on the `before_provider_request` hook, which pi/omp run for main agent turns only.
- **Gateway-routed** ids are the canonical gateway model IDs, left unpinned — the gateway picks the host. They need no rewrite, so they also work for internal side requests (session titles, compaction summarization, handoff), which skip the hook. Costs below are the host the gateway routes to today.

> **Side requests need a gateway-routed id.** Session titles, compaction
> summarization, and handoff are generated by pi/omp side requests that never run
> extension hooks, so a host-pinned id reaches the gateway unrewritten and is
> rejected (`404 Model 'fireworks/deepseek-v4.1-flash' is not supported`).
> Compaction then falls through to its last-resort candidate — the
> largest-context model available — and can fail there (e.g. Bedrock Llama 4
> Scout's 8192-token output cap vs the summarizer's 13107-token budget). Pick a
> gateway-routed id when you rely on those flows, or point `compactionModel` /
> `modelRoles.smol` at one.

Pick via `/model` in pi. All models support:

- **Reasoning:** DeepSeek routes take the full `none` … `max` ladder; GLM takes `low` / `high` / `max` (pi's other levels fold into those)
- **Prompt caching:** automatic (Z.AI and DeepSeek are automatic-cache routes). Gateway ignores `X-Session-Id` header, respects body `prompt_cache_key`. Extension injects pi session ID as `prompt_cache_key` for the Particle and Fireworks routes; existing keys preserved.

## How routing works

The gateway can route a single model to any host. Host-pinned model IDs
(`particle/…`, `fireworks/…`) are rewritten to the real gateway model ID and carry a
`vendor` field that pins the host (see `routing.ts`), so pi's cost display matches the
host that bills. Gateway-routed IDs are already gateway model IDs and are sent
untouched: no rewrite, no pin, the gateway picks.

A pinned vendor must also be able to serve the model for your organization — otherwise
the gateway refuses the request (`vendor_restrictions_unavailable` or
`vendor_unavailable`). The response carries `x-merge-vendor` with the host that
actually served it.

The pin can only be applied from the `before_provider_request` hook, which runs for
main turns only (pi `sdk.ts` → `emitBeforeProviderRequest`). Side requests — session
titles, compaction summarization, handoff, `judge()` — build their payload from the
model entry directly, so they can only reach the gateway with a gateway-valid model
ID. That is what the gateway-routed entries are for.
